# Connect the book club website to Supabase The site uses Supabase to share RSVPs, book updates, and comments across visitors. Phone numbers and availability submissions are stored separately and cannot be read through the public website key. ## 1. Create the database tables 1. Create a Supabase project at [supabase.com](https://supabase.com/). 2. In your project, open **SQL Editor** and start a query. 3. Copy all of `supabase-setup.sql` into the query and run it. The script enables row-level security. The public website can submit records and read only public book-club activity. Phone/contact rows and individual RSVPs are not readable by the public key; the RSVP section gets only an aggregate attendee count. Reader updates use `reader_data` JSON to store multiple books, page counts, finished status, and the selected goal. ## 2. Add the public project settings to the site In the Supabase dashboard, open your project's **API settings** and copy: - The **Project URL** - The **publishable key** (or the legacy `anon` key) In `HTMLPage1.html`, replace the two values near the top of its last script: ```js const SUPABASE_URL = 'https://YOUR_PROJECT_ID.supabase.co'; const SUPABASE_ANON_KEY = 'YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY'; ``` The publishable/anon key is intended to be visible in a website. **Never use or publish a `service_role` or secret key**; those keys bypass database protections. The row-level security policies in the SQL file are required for safe browser access. ## 3. Publish and test Commit/push the changed HTML and `supabase-setup.sql` to the GitHub repository used by GitHub Pages. After Pages finishes deploying, test an RSVP, a comment, and a reading update. Refresh the site and check that public entries and the RSVP count remain visible. In Supabase, use **Table Editor** to view the tables. `contact_submissions` contains names, phone numbers, and availability, so keep access to that table limited to trusted project administrators. The site does not provide an admin interface for private submissions. Existing entries in browser Local Storage are not transferred automatically. This setup starts a shared Supabase database for new submissions. Because the public forms accept anonymous submissions, add CAPTCHA or another abuse-prevention step if the site starts receiving spam; do not try to solve that by exposing a secret key in the page.
